# 安全模型

## 1. 威胁来源

- 恶意或被污染的论文文本可能诱导模型生成危险代码。
- LLM 生成的 Python/MATLAB 代码可能访问网络、文件系统、进程或环境变量。
- 解析复杂 PDF 的第三方程序可能存在资源消耗或解析漏洞。

## 2. 当前防护

### 静态检查

Python 使用 AST 扫描：

- `subprocess`、`socket`、危险 `os` 调用。
- `eval`、`exec`、`compile`、动态导入。
- 可疑文件删除和网络库。

MATLAB 使用规则扫描：

- `system`、shell escape、`unix`、`dos`。
- `delete`、`rmdir`、网络 URL 访问等。

### 运行限制

- 子进程超时。
- POSIX 下设置 CPU、地址空间、文件大小和进程数上限。
- 临时 HOME。
- 只保留少量系统环境变量，移除 API Key 等敏感变量。

## 3. 明确不保证的事情

这不是完整的 OS 沙箱。静态规则可能漏检，Windows 上资源限制也弱于 POSIX。正式执行未知代码时，优先使用：

- 无密钥、无私人文件挂载的 Docker 容器。
- 临时 WSL 发行版。
- 虚拟机或专用比赛环境。

## 4. 操作建议

1. 先阅读 `validation.json`。
2. 检查 `AI_INFERRED` 参数与依赖。
3. 不给代码运行容器挂载整个用户目录。
4. 网络默认关闭。
5. 将原始论文、IR、生成代码和结果分别提交 Git，以便审计。
